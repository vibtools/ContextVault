# ContextVault Code of Conduct

## Our standard

ContextVault welcomes respectful participation from users, contributors, maintainers, security researchers, and reviewers.

Participants are expected to:

- communicate professionally;
- discuss technical ideas rather than attacking people;
- provide evidence for claims;
- accept constructive review;
- respect privacy and confidential security reports;
- avoid harassment, discrimination, threats, and intimidation;
- avoid publishing another person's private information;
- avoid disruptive or deliberately misleading behavior.

## Technical disagreements

Strong technical disagreement is allowed. Keep discussion focused on observable behavior, reproducible evidence, project requirements, compatibility, security, maintainability, and user impact.

Do not use personal insults, ridicule, or repeated bad-faith arguments.

## Security and private data

Never publish credentials, session cookies, private Chrome profiles, personal conversation content, unredacted security vulnerabilities, or another person's private logs or files.

Follow [SECURITY.md](SECURITY.md) for vulnerability reporting.

## Maintainer responsibilities

Maintainers may edit, hide, lock, or remove content that violates this policy. They may temporarily or permanently restrict participation when necessary to protect the community or project.

Enforcement decisions should be proportional, documented when practical, and focused on project safety.

## Reporting conduct problems

Report serious conduct problems privately to the maintainers. Do not include sensitive personal information in a public issue.

## Scope

This code applies to repository issues, pull requests, reviews, discussions, release communication, and other spaces where a person represents the ContextVault project.

## Attribution

This policy is an original project conduct standard informed by common open-source community practices.
